# Member-owned regional depth discovery

Link the nine existing parent rows in current-depth-member-index-v7 to the
unchanged v35 regional projection inventory. Reuse precisely their declared
catalog members and provenance. This is evidence discovery, not a new taxonomy
admission. The length convention's longest-member or segment-sum operator is
never transferred to depth. Parent scalar depths, ranges and volumes stay null.

Each link resolves the original immutable JSON piece, hash, collection, pointer,
case ID and owner. Preserve available phase/date, campaign, branch, analysis
window, method, cutoff and assumptions. Unknown dates remain unknown. Supported
and unresolved cases remain separate. Do not copy numerical depth fields to
parent records or combine noncontemporaneous extrema. Shared members/cases are
deduplicated globally rather than counted as independent measurements.

Audit all entries lacking their own supported cases. Distinguish declared-member
discovery, other system scope, unresolved regional cases and not-yet-collected
individual current estimates. Member discovery does not change own-current
coverage or fill individual gaps. The original 83 owners, 227 supported cases,
18 unresolved cases and all original depth/eddy records remain untouched.

Build joins and run integrity tests only in the cloud, sequentially on one idle
CPU. No field retrieval, new numerical kernels, geometry processing or source
measurement collection. Local preparation and exact hash/artifact retention only.
No runtime, browser, query UI or server execution/integration. Fixed publication
caps remain 2.5MB per file and 3MB per batch; do not expand the frozen register.
This is a collection/discovery improvement, not completion of the depth programme.
