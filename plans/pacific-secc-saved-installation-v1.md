## Execution and custody

The default request is disabled. A specific activation permits one cloud job,
one CPU, and low scheduling priority. No source editing occurs while that job
is live. The global source-review phase stays disabled for heavy work.

No native/WASM build, browser run, original ocean-field processing, packet
decoding, local large download, generated preview synchronization, or main
merge is authorized by the installation request.

The installer checks exact source/preflight hashes, the currently installed
parent manifest and generated files, disabled older requests, saved test
results, visual-review hashes, and authoritative successful source runs.
It downloads the two artifacts only in cloud, checks ZIP sizes/digests,
rejects changed or unsafe member inventories, and checks every file hash.
The overlay changes only its four declared presentation paths; eighteen
scientific candidate files are preserved exactly. The final manifest must
match the retained reviewed manifest byte for byte and preserve the EACC
and earlier scientific delivery namespaces.

Twenty-two generated paths plus a proof and a disabled request are the entire
allowed Git Tree API transaction. Old packet parts and unrelated source files
are retained. Every uploaded blob's Git object ID, candidate file size and
protected path object is checked before a nonforce ref update. The parent
branch head and main are checked again immediately before that update.
The resulting files and unchanged main are verified afterwards.
