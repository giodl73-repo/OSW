# Published model layer and depth context, version1

1. Bind the accepted catalogue identity, primary publication, inspected prose,
   model/component, analysis period and review scope. Preserve absence of local
   original custody and do not invent a PDF checksum or source-figure review.
2. Author-defined analysis bands have their own quantity class. A definition of
   a surface layer is not measured current thickness, an averaging instruction
   for other data, or an annual depth interval.
3. Approximate mean-core depths, threshold-depth caps and exact current edges
   remain different quantities. Keep source approximation and inequality;
   missing exact edges, uncertainty and dates remain null.
4. Associate only the stated surface feature with its accepted surface-current
   owner. Related undercurrent records retain a related-current reference and
   source feature label, with no invented canonical undercurrent identity.
5. Store model layer definitions and model depth context in distinct
   collections. Do not add width samples, current identities, ranked lengths,
   observed velocities, physical geometry/state joins or seasonal playback.
6. One study summary does not become a set of independent observations. An
   analysis-year span is not a measured annual dimension range. Grid spacing
   and selected meridians do not establish current width or paired edges.
7. Bind source facts, reviewed figure, renderer and role review by exact hashes.
   Retain source and method references on every row. Keep the original numeric
   values and caveats; rendering labels may not rewrite records.
8. Append only after checking all collections, owner identity, prior references,
   source registry, collisions and contract contents. Prepare affected rows in
   memory, then commit together. Refuse duplicate application or unresolved
   provenance; preserve other objects, dimensions and context unchanged.
9. Separate prepared query contracts from installed packets and verified UI.
   Use tiny offline checks during preparation. Any packet publication/build or
   browser verification is a separate, serial cloud stage under the resource
   limits. No local full-packet load or native/WASM rebuild is required here.
