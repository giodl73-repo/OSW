# South Java sequential native source check

Before producing an installed-data candidate, compile the changed Rust source
and run the selected source/planning/catalogue tests in one cloud job. Keep
Cargo and numerical workers at1, CPU affinity at1, and scheduling priority
at nice15. The global source-review phase remains disabled for heavy work;
only the specific native-source request authorizes this case.

Verify the frozen runtime/query contracts, source scope, exact parent archives,
lockfile and complete declared source hashes before compilation. Run12 small
Python tests and a syntax-only atlas JavaScript check. Then run five Rust test
namespaces sequentially: South Java5, Pacific SECC5, planning6, northwest
Australian reference4, Madagascar curve4 (24 tests total).

Use a request-only selector and a sparse source checkout. Select the Rust crate,
its literal compiled/test data references and the pinned Python/metadata paths.
Exclude the query packet parts, index payload, WASM binary and original ocean
fields. The source check may compile the small index catalogue embedded by the
crate, but does not initialize or query the installed index payload.

Retain compact compiler/test logs and receipts. Do not upload native build
outputs or promote scientific data. Packet/index candidate construction,
actual native/WASM response equality, browser navigation/mobile review and
guarded installation remain separate required delivery gates.
